model only specified a string column; the prefix is generated by the API when creating
an ID. The first API test run also exposed an incorrect headers argument in the
problem-response helper, which was fixed after the test failure.

## In my own words

1. Why does a transfer to someone else's account return 404 and not 403?
   
   A 404 avoids revealing whether an account exists or belongs to another customer.
   This helps prevent account enumeration.

2. What would happen to a customer if your idempotency record were written in a separate transaction after the transfer?

   If the transfer committed but the idempotency record failed, a retry could execute
   the transfer again because the server would not know the key was already used.
   This could debit the customer twice, so both operations must commit atomically.
